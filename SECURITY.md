# Security Policy

RouteFoundry Technologies takes security issues seriously and prefers responsible, private disclosure.

## Reporting a vulnerability

Do **not** open a public GitHub issue for a suspected vulnerability, exposed secret, authentication weakness or other security-sensitive finding.

Instead, contact RouteFoundry through **https://routefoundry.co.za/contact** and clearly state that the message concerns a **security vulnerability**.

For the initial contact:

- identify the affected repository, service or URL;
- provide a concise description of the suspected issue;
- explain the potential impact if known; and
- provide a safe way for RouteFoundry to contact you for technical details.

Please do not include live credentials, personal information, destructive proof-of-concept payloads or sensitive exploit details in the first message.

RouteFoundry will arrange a suitable private channel for any information that should not be submitted through the public contact flow.

## Good-faith research

Please avoid actions that could:

- access or modify data that does not belong to you;
- degrade or interrupt production services;
- expose credentials or personal information;
- create persistence or backdoors;
- perform social engineering, phishing or physical attacks; or
- cause financial or operational harm.

## Scope and support

Individual repositories may provide additional security guidance or define a narrower support boundary. Repository-specific security policies take precedence over this organization default.

A public repository does not necessarily mean that RouteFoundry offers a public bug bounty, security reward or support commitment.
